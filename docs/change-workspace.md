# 统一文件修改工作区

旧右栏把“整个项目的修改”和“当前对话的项目外文件”拼成一个列表，范围不一致；点击后分别进入项目与journal两个详情面板。会话解除项目关联后，项目修改无法从旧详情入口正常查看。用户要求继续重做前后端与UI，这次先完整整理文件结果、差异和撤回流程。

新的后端read model从执行会话、Run和持久修改记录计算统一列表。默认当前对话；整个项目显式切换，包含项目下其他对话的修改。历史任务保留原归属，即使当前会话解除项目关联仍可查看。列表分页带revision，撤回导致版本变化时要求重读，列表本身不读取文件内容；详情只读选中记录的文件，保存前后文本沿现有可靠读取与脱敏实现。

前端右栏采用统一卡片和详情组件：文件名与保存状态、打开文件、展开差异、撤回这次修改。项目与journal保存后的记录使用同一界面；撤回继续交各自已有版本机制。未保存提案保留原接受流程。刷新中暂停操作，外部改动时保留历史差异和当前冲突；操作完成后即便已切换对话也会刷新当前文件工作区。移除旧SessionChangesPanel、useSessionFileChanges、fileChangeLabels和旧混合列表实现。

这次没有重写Agent执行器和全部页面，也未将传输完成当成任务成功。完整任务完成状态、对话成果卡、主聊天信息层级、模型设置和子Agent生命周期仍是后续产品重构范围。
