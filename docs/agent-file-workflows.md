# Agent 文件工作流修复

本轮修复读取、编辑、产物导航之间的实际断点，同时删除没有真实入口的旧机制。公开分支先同步当前可运行的通用工作台源码，再单独提交下列修复，避免把开发机的私人 Git 历史带到远端。

## 行为变化

- 项目、本机文件和 Skills 使用相同分页计算。长行可按字符偏移继续读取，行号只描述实际返回的文字；Skills 增加 `start_offset` / `next_offset`。
- 项目相对路径始终属于该项目。项目缺失或文件找不到时返回真实错误，不偷偷改到主目录读取同名文件。
- 明确指定的配置文件可以走统一文件工具。快照不收录的路径复用 FileChangeJournal；工具结果仍脱敏，编辑保留编码、BOM、换行、并发比较与撤回。
- 删除重复正文 Hashline 与失效的内存账本。编辑继续基于精确文本匹配和真实提交时的文件版本。
- `edit_file` 保持单处 `find` / `replace`，增加 `edits[]`。所有替换先在内存完成，任一项不匹配则整批不保存，成功只提交一次。
- 本机读取回执包含编码、BOM、换行和 SHA-256，编辑描述明确已有格式保留能力，让模型能直接选用文件工具。
- 自由对话的项目外产物可预览、复制、引用和重新读取。Windows、POSIX、localhost、UNC 文件地址正确解析；迟到读取按会话隔离，撤回后读取真实磁盘。
- 普通网页链接接桌面共享浏览器。启动期间先恢复会话归属再开放输入，已有会话离线仍可编辑草稿。
- 删除无装配/调用者的旧四技能连续审批服务、只测实现内部集合的 Hashline 测试、以及读取私人书库且缺书就返回通过的两项测试。保留临时样本验证和历史收据模型。

## 采用的旧项目机制

| 项目 | 值得保留 | 本次决定 |
| --- | --- | --- |
| 织梦写作台 Pro | 顺序文本替换、全部计算后单次保存 | 批量编辑进入当前工具和 journal；固定轮数停止、重复实现不搬入 |
| 文渊阁 | Office 提取、实际文件操作的历史事实 | Office 已在当前版本适配；文件历史继续复用当前 journal，小说流程留在 Skills |
| 旧打包项目 | 长行游标、附件来源、持久队列的版本与幂等 | 补齐分页和产物导航；当前服务端队列已有对应能力，不重复建立本地/网关双镜像 |

这是按机制评估与采用，不是逐行审完三个历史仓库。独立旁问、完整子 Agent 生命周期、长期记忆质量、安装发行仍未包含在这次修复中。
