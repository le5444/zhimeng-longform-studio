## 后续开发快照的唯一入口

使用 [`scripts/dev_snapshot.py`](../scripts/dev_snapshot.py)，只依赖 Python 标准库：

```powershell
# 在线 SQLite 一致性快照：包含已提交 WAL，临时原始副本自动清理
python scripts/dev_snapshot.py capture .runtime/workbench.sqlite3 before-runtime-change

# 归档一份已经关闭的开发快照：按原字节压缩，源文件仍保留
python scripts/dev_snapshot.py archive .runtime/my-task/formal-before.sqlite3 my-task-before

# 恢复到不存在的新文件；后续真正回滚仍走产品既有恢复流程
python scripts/dev_snapshot.py restore before-runtime-change .runtime/recovery/check.sqlite3
```

默认集中到 `.runtime/dev-snapshots/objects/<sha256>.sqlite3.gz`，任务标签只保存小 JSON 引用；内容一致的快照共用一个对象。标签不能覆盖另一版本。每次存储与恢复校验解压内容。`--store` 可以选择其他工作目录的存储入口。

现有 `BackupService` 继续负责产品备份、维护锁及正式恢复。新脚本收拢原本散落的开发快照操作，不提供另一套产品恢复 API。普通界面修改和只读核查无需复制正式数据库；集成验证从空临时库及小夹具开始，需要真实数据时才明确创建开发快照。日志/XML 与大临时目录分开。已存历史验收脚本作为证据保留，新任务使用这里的入口；仍手写复制脚本会继续增长，工具本身不会自动接管它们。
